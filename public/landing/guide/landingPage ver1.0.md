# tryna Landing Page ver 1.0

## 개요

tryna는 캘린더 서비스이지만, **생산성 향상을 위한 일정 관리를 표방하지 않습니다.**

우리는 사람들이 더 많은 일을 계획하고, 더 효율적으로 시간을 관리하며, 모든 일을 완벽하게 해내야 한다고 생각하지 않습니다. 오히려 일정과 함께 따라오는 수많은 준비와 해야 할 일을 계속 기억하고 신경 써야 하는 부담을 줄이는 것에 집중합니다.

일정은 기억했지만 준비물을 놓치거나, 해야 할 일을 뒤늦게 떠올리고, 혹시 무언가 잊은 것은 없는지 반복해서 확인하는 일은 일상에서 자연스럽게 발생합니다. tryna는 이러한 작은 놓침을 줄이고, 사용자가 모든 것을 스스로 기억하려 애쓰지 않아도 필요한 순간에 필요한 것을 자연스럽게 챙길 수 있도록 돕고자 합니다.

따라서 tryna의 랜딩페이지 역시 **‘더 많이 해내는 생산성’보다 ‘덜 신경 써도 되는 일상’이라는 웰니스의 관점**에서 서비스를 전달합니다.

기능의 우수성이나 관리 효율을 먼저 설명하기보다, tryna를 통해 사용자의 하루가 어떻게 달라지는지를 보여줍니다. 일정과 연결된 작은 것들을 함께 기억하고, 필요한 순간에 다시 떠올려줌으로써 사용자가 자신의 일상에 조금 더 마음을 놓을 수 있는 경험을 전달하는 것이 랜딩페이지의 핵심 방향입니다.

## 핵심 방향

> **생산성을 높이는 캘린더가 아니라, 일상의 작은 것들을 덜 놓치고 조금 더 마음 놓을 수 있도록 돕는 캘린더.**

랜딩페이지는 **기능 → 효율 → 성과**의 전통적인 생산성 서비스 문법보다, **일상 → 공감 → 안도 → 경험**의 흐름을 중심으로 구성합니다.

## 구조 원칙

기존의 문제 정의, 핵심 기능, 사용 후 변화, 사용 방법을 각각 독립된 섹션으로 나누지 않습니다. 사용자가 한 가지 일상 장면을 따라가는 동안 문제와 tryna의 작동 방식, 사용 후 변화가 바로 이어지도록 구성합니다.

각 요소를 설명하는 랜딩페이지보다 **문제와 솔루션이 한 세트로 읽히는 랜딩페이지**를 지향합니다.

```text
감각적인 첫인상
→ 브랜드 철학 이해
→ 내 일상과의 공감
→ 문제와 솔루션을 하나의 장면으로 경험
→ 효용과 신뢰 형성
→ 시작하기
```

전체 페이지는 다음의 여섯 영역으로 구성합니다.

1. 메인 비주얼 배너
2. tryna가 생각하는 웰니스
3. 일정에서 준비까지 이어지는 핵심 경험
4. 사용자의 선택권과 신뢰
5. 최종 CTA
6. 팀 정보 푸터

## Section 1. 메인 비주얼 배너

화면 대부분을 채우는 하나의 강한 이미지 또는 짧은 영상을 사용합니다.

### 목적

- 첫 화면에서 브랜드 분위기 형성
- 캘린더 앱보다 웰니스 브랜드에 가까운 첫인상 제공
- 설명을 읽기 전에 tryna가 추구하는 일상의 상태 전달

### 이미지 방향

제품 화면을 크게 배치하는 대신, **일정과 준비가 함께 발생하는 일상의 한 장면**을 보여줍니다.

예시 장면:

- 여행을 앞둔 가방과 여권, 보조배터리
- 발표를 앞둔 책상 위 노트북과 발표 자료
- 외출 직전 현관에 놓인 가방, 우산, 열쇠
- 친구 생일 약속과 함께 놓인 작은 선물
- 관공서 방문 전 준비된 신분증과 서류

이미지 안에는 제품 UI 전체가 아니라, tryna가 제안한 준비물이나 해야 할 일이 적힌 작은 카드 정도만 노출합니다.

### 히어로 카피

> **일상의 작은 것들을 놓치지 않도록.**

일정은 기억해도  
그날 필요한 것까지 모두 기억하기는 어려우니까.

`tryna 시작하기`

### 운영 방식

초기 랜딩에서는 여러 장을 자동 전환하는 캐러셀보다 하나의 강한 메인 비주얼을 사용합니다. 추후 계절이나 캠페인에 맞춰 메인 이미지만 교체할 수 있도록 설계합니다.

- 여름: 여행, 장마, 야외 일정
- 개강: 수업, 팀 프로젝트, 발표
- 연말: 약속, 선물, 모임
- 일상: 출근, 병원, 관공서 방문

## Section 2. tryna가 생각하는 웰니스

tryna가 생산성 앱과 무엇이 다른지를 선언하는 영역입니다. 독립된 가치 설명을 길게 이어가기보다, 핵심 경험으로 넘어가기 위한 짧은 브랜드 챕터로 사용합니다.

### 카피

> **잘 살아간다는 건  
> 모든 것을 기억하는 게 아니니까.**

우리는 사람들이 더 많은 계획을 세우고  
모든 일을 완벽하게 관리해야 한다고 생각하지 않습니다.

중요한 순간에 필요한 것들을 덜 놓치고,  
계속 신경 쓰지 않아도 되는 일상.

tryna는 그런 하루를 돕는 캘린더를 만듭니다.

### 세 가지 가치

| 가치 | 설명 |
| --- | --- |
| **잘 기억하기** | 중요한 일정과 연결된 맥락을 함께 기억한다. |
| **잘 챙기기** | 필요한 준비물과 해야 할 일을 자연스럽게 확인한다. |
| **마음 놓기** | 혹시 놓친 것이 없는지 계속 신경 쓰는 부담을 줄인다. |

> 카피의 주체는 후속 카피 정리 단계에서 통일합니다. `잘 기억하기`는 사용자가 기억을 잘한다는 의미가 아니라, tryna가 대신 함께 기억한다는 의미로 표현해야 합니다.

## Section 3. 일정에서 준비까지 이어지는 핵심 경험

기존의 `우리가 자주 놓치는 순간`, `tryna 핵심 경험`, `사용자가 얻게 되는 변화`, `tryna를 사용하는 방법`을 하나의 연속된 섹션으로 병합합니다.

이 영역에서는 문제를 모두 설명한 뒤 기능을 따로 소개하지 않습니다. 하나의 일상 장면 안에서 **문제 → 입력 → 제안 → 변화**가 바로 이어지도록 보여줍니다.

### 섹션 도입

> 우리는 일정을 잊는 것보다  
> **일정에 딸린 작은 것들을 더 자주 놓칩니다.**

문제를 과도하게 심각하게 묘사하지 않고, 누구나 겪는 자연스러운 일상 장면으로 보여줍니다.

### Scene 1. 발표 일정

#### 문제

> **발표 일정은 기억했지만**

- 발표 자료 최종본 저장
- 노트북 충전
- USB 준비

#### tryna 경험

**01. 말하듯 적어요**

복잡한 입력창 없이 평소 사용하는 문장으로 일정을 기록합니다.

> 금요일 3시 졸업 프로젝트 발표

**02. 필요한 것을 제안받아요**

tryna가 일정의 맥락을 이해하고 준비물과 해야 할 일을 먼저 제안합니다.

- 발표 자료 최종 점검
- 발표 연습
- 노트북 준비
- 팀원에게 최종본 공유

#### 변화

> **따로 정리하지 않아도**

일정과 준비물을 여러 앱에 나누어 적는 과정을 줄입니다.

### Scene 2. 여행 일정

#### 문제

> **여행 날짜는 기억했지만**

- 온라인 체크인
- 신분증 확인
- 보조배터리 챙기기

#### tryna 경험

일정이 입력되면 여행에 필요한 준비와 행동이 일정에 연결되어 함께 나타납니다.

> 토요일 제주도 여행

- 온라인 체크인
- 신분증 확인
- 보조배터리 챙기기

#### 변화

> **매번 다시 찾지 않아도**

필요한 준비와 행동이 일정에 연결되어 함께 보입니다.

### Scene 3. 병원 일정

#### 문제

> **병원 예약은 기억했지만**

- 이전 검사 결과 준비
- 복용 중인 약 확인
- 보험 관련 서류 챙기기

#### tryna 경험

**03. 필요한 순간 다시 확인해요**

일정 전 적절한 시점에 준비와 행동을 확인합니다.

> 다음 주 화요일 병원 방문

- 이전 검사 결과 준비
- 복용 중인 약 확인
- 보험 관련 서류 챙기기

#### 변화

> **모든 것을 기억하지 않아도**

필요한 순간에 tryna가 다시 보여줍니다.

### 핵심 아하 모먼트

세 장면을 거치며 반복해서 전달해야 하는 핵심 경험입니다.

> **일정 하나만 적었는데,  
> 챙겨야 할 것들이 함께 정리됩니다.**

제품 UI에서는 다음 흐름을 짧은 인터랙션이나 스크롤 애니메이션으로 보여줍니다.

1. 자연어 일정이 입력됩니다.
2. 날짜와 시간이 일정 카드로 변환됩니다.
3. 준비물과 해야 할 일이 자연스럽게 나타납니다.
4. 사용자가 불필요한 항목을 수정하거나 삭제합니다.

### 섹션 마무리

> **기억해야 할 것이 줄어들면  
> 하루도 조금 가벼워집니다.**

### 표현 원칙

기술 구조는 전면에 내세우지 않습니다.

| 내부 기술 표현 | 사용자 표현 |
| --- | --- |
| 자연어 파싱 | 말하듯 적어요 |
| 온톨로지 기반 추론 | 일정의 맥락을 이해해요 |
| LLM 추천 | 필요한 것을 먼저 제안해요 |
| 컨텍스트 기반 알림 | 필요한 순간 다시 알려줘요 |

### 화면 구성 원칙

- Scene 1, 2, 3을 각각 독립된 카드 섹션처럼 강하게 분리하지 않습니다.
- 하나의 제품 UI를 화면 한쪽에 고정하고, 스크롤에 따라 일상 장면과 일정 내용이 바뀌는 구성을 우선 검토합니다.
- 사용자가 문제를 본 직후 같은 화면 안에서 tryna의 제안을 확인할 수 있도록 합니다.
- 문제와 솔루션 사이에 별도의 기능 소개 섹션이나 긴 설명을 삽입하지 않습니다.
- 세 장면은 하나의 긴 핵심 경험처럼 이어져야 합니다.

```text
발표 일정은 기억했지만
→ 일정 입력
→ 준비와 행동 제안
→ 따로 정리하지 않아도

여행 날짜는 기억했지만
→ 일정 입력
→ 준비와 행동 제안
→ 매번 다시 찾지 않아도

병원 예약은 기억했지만
→ 일정 입력
→ 준비와 행동 확인
→ 모든 것을 기억하지 않아도
```

## Section 4. 사용자의 선택권과 신뢰

AI가 사용자의 일정을 임의로 결정하는 것이 아니라, 먼저 제안하고 사용자가 수정하는 구조임을 짧게 보여줍니다.

이 영역은 독립된 설명 섹션처럼 길게 구성하지 않고, Section 3의 제품 인터랙션이 끝난 뒤 이어지는 에필로그처럼 배치합니다.

### 카피

> **tryna가 먼저 제안하고,  
> 결정은 언제나 사용자가 합니다.**

- 필요한 항목만 선택
- 잘못된 제안은 삭제
- 직접 항목 추가
- 사용자에 따라 점차 달라지는 제안

제품 화면에서는 항목을 선택하고, 수정하고, 삭제하는 모습을 직접 보여줍니다.

## 전체 사용자 감정 흐름

```text
감각적인 첫인상
→ 브랜드 철학 이해
→ 내 일상과의 공감
→ 문제를 본 직후 해결 경험 확인
→ 사용 후 변화 체감
→ 선택권과 신뢰 확인
→ 시작하기
```

일반적인 SaaS 랜딩의 `기능 → 장점 → 가격` 구조가 아니라 다음의 흐름을 사용합니다.

> **일상 → 공감 → 경험 → 안도 → 신뢰 → 행동**

## 비주얼 방향

### 핵심 키워드

- 일상적
- 편안함
- 가벼움
- 자연스러움
- 정돈된 여백
- 따뜻한 신뢰
- 지나치게 감성적이지 않은 웰니스

### 이미지 원칙

- 사람이 사용 중인 앱 화면보다 **일정과 연결된 현실의 오브젝트**를 중심으로 합니다.
- 스톡 이미지처럼 과도하게 웃는 인물 사진은 피합니다.
- 이미지마다 일정, 준비물, 행동이 연결되는 맥락이 있어야 합니다.
- 캘린더 그리드나 체크 표시를 장식적으로 남용하지 않습니다.
- 제품 UI는 서비스 이해를 돕는 최소한의 레이어로 사용합니다.
- 라이프스타일 이미지와 제품 UI를 완전히 분리하지 않고 같은 장면 안에서 연결합니다.

### 주의할 점

웰니스 분위기만 강조하면 tryna가 무엇을 하는 서비스인지 모호해질 수 있습니다. 첫 화면에서는 감정을 전달하되, Section 3에 진입하는 즉시 일정 입력과 준비 항목 제안 경험을 보여줍니다.
